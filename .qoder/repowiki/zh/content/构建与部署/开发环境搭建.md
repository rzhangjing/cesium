## 简介
本指南面向首次参与 Cesium 前端开发的工程师，目标是帮助你在本地快速、稳定地搭建可构建、可调试、可提交的环境。内容覆盖 Node.js 版本与安装（含 nvm）、npm 依赖管理与镜像缓存优化、TypeScript 编译配置、代码编辑器与 ESLint 集成、Git 工作流（husky 钩子与 pre-commit 检查），以及常见环境问题的定位与解决思路。**新增**：随着项目引入Rust多包工作区架构，本指南现在包含完整的Rust开发环境配置，支持domain-driven设计的模块化架构。

## 项目结构
Cesium 仓库采用多包与脚本驱动的工程化组织方式，现已扩展为支持JavaScript/TypeScript与Rust混合开发的现代化架构：
- 顶层 package.json 定义 Node 版本要求、脚本命令与依赖；
- .npmrc 管理 npm 行为（如缓存、镜像等）；
- tsconfig.json 提供 TypeScript 编译选项；
- eslint.config.js 统一代码风格与静态检查；
- gulpfile.js 与 scripts/build.js 负责构建流程；
- server.js 提供本地开发服务器；
- **cesiumrust/** 目录包含全新的Rust多包工作区，采用领域驱动设计架构；
- Documentation/Contributors 下包含官方构建与 VSCode 使用指南；
- CONTRIBUTING.md 描述贡献流程与规范。

## 核心组件
- Node.js 与版本管理
  - 通过 package.json 的 engines 字段声明所需 Node 版本范围，建议使用 nvm 在本地切换并锁定版本，避免团队差异导致的构建失败。
- npm 依赖与缓存
  - 使用 .npmrc 统一管理缓存路径、网络超时、镜像源等；结合国内镜像加速依赖安装与构建。
- TypeScript 编译
  - 基于 tsconfig.json 控制模块解析、目标平台、输出目录、类型检查严格度等关键项。
- 代码质量与编辑器
  - 使用 eslint.config.js 进行规则配置，配合 VSCode 扩展实现保存时自动修复与错误提示。
- 构建与服务
  - gulpfile.js 作为构建入口，scripts/build.js 承载具体构建步骤；server.js 提供本地预览服务。
- Git 工作流
  - 通过 lint-staged 与 husky 在提交前执行检查，保证代码质量基线。
- **Rust 工具链与工作区**
  - **新增**：使用 Cargo 工作区管理多个Rust包，支持领域驱动设计的模块化架构，包含domain、adapters、ports和application四个主要层次。

### 各层次职责说明

#### 领域层(Domain Layer)
- **geospatial**：地理空间坐标转换、投影计算、距离测量等核心算法
- **tileset**：3D瓦片集的加载、管理和渲染逻辑
- **imagery**：卫星影像、地图图层的处理和显示
- **camera**：三维相机的控制、视角变换和导航
- **terrain**：地形数据的加载、裁剪和细节层次管理
- **time**：时间相关的功能，包括动画、时间轴和时间插值
- **event**：事件系统和消息传递机制
- **resource**：资源的生命周期管理和内存优化

#### 适配器层(Adapters Layer)
- **bevy-render**：基于Bevy游戏引擎的渲染适配层
- **decoders**：各种数据格式的解码器实现
- **network**：网络请求和数据传输的抽象层

#### 端口层(Ports Layer)
- **driving**：应用层调用的接口定义
- **driven**：外部系统的接口抽象

#### 应用层(Application Layer)
- **cesium-app**：主应用程序入口点
- **bevy_demo**：基于Bevy的演示应用程序

### Rust开发工作流程
- **构建整个工作区**：`cd cesiumrust && cargo build`
- **构建特定包**：`cargo build -p geospatial`
- **运行测试**：`cargo test`
- **代码格式化**：`cargo fmt`
- **代码检查**：`cargo clippy`
- **发布构建**：`cargo build --release`

### VSCode Rust开发配置
- 推荐扩展：
  - rust-analyzer：智能代码补全和类型检查
  - Better TOML：TOML配置文件语法高亮
  - Error Lens：错误信息内联显示
  - Code Spell Checker：拼写检查
- 配置建议：
  - 启用保存时自动格式化
  - 配置rust-analyzer的索引和诊断选项
  - 设置TOML文件的格式化和验证

## 性能考虑
- 依赖安装

- **Rust构建优化**

- **混合构建优化**
  - **新增**：并行执行JavaScript和Rust构建；使用构建缓存减少重复编译；按需构建特定的Rust包。

## 故障排查指南
- Node 版本不匹配
  - 现象：构建报错提示 Node 版本过低/过高。
  - 处理：使用 nvm 安装并切换到 package.json engines 指定的版本。
- 依赖安装缓慢或失败
  - 现象：下载超时、连接中断。
  - 处理：在 .npmrc 中配置国内镜像与缓存目录；必要时调整网络超时与重试策略。
- TypeScript 类型错误或编译失败
  - 现象：大量类型错误或找不到模块。
  - 处理：检查 tsconfig.json 的 target/module/paths 配置；清理构建缓存后重试。
- ESLint 报错无法提交
  - 现象：pre-commit 被拦截。
  - 处理：根据 eslint.config.js 提示修复问题；必要时在 VSCode 中启用保存时自动修复。
- 本地服务无法访问
  - 现象：打开页面空白或端口占用。
  - 处理：确认 server.js 启动成功，释放冲突端口；检查浏览器控制台错误。
- **Rust工具链问题**
  - **新增**：现象：cargo命令不可用或版本不兼容。
  - **新增**：处理：重新安装rustup；使用rustup update更新工具链；检查PATH环境变量。
- **Rust依赖解析失败**
  - **新增**：现象：cargo build时报错找不到依赖。
  - **新增**：处理：清理Cargo缓存(cargo clean)；检查网络连接；使用cargo update更新依赖。
- **混合构建冲突**
  - **新增**：现象：JavaScript和Rust构建相互影响。
  - **新增**：处理：分离构建脚本；使用并行构建；检查输出目录冲突。
