仓库采用多语言、多工作区架构：
- JavaScript/TypeScript 层：以 npm workspaces 组织 `packages/engine`（核心渲染与地理空间能力）、`packages/widgets`（UI 组件）、`packages/sandcastle`（在线示例），由根 `gulpfile.js` + `scripts/build.js` 通过 esbuild 构建为 ESM/IIFE/CJS 产物并输出到 `Build/`；源码入口为 `Source/Cesium.js`，并通过 `index.cjs` 暴露 CommonJS 兼容接口。
- 构建与工具链：Gulp 任务编排 esbuild 打包、GLSL 转 JS、Worker 捆绑、JSDoc 生成、Karma/Jasmine 单元测试与 Playwright e2e 测试；`.husky` 钩子与 `eslint.config.js`、`prettierrc`、`sgconfig.yml`（ast-grep）统一代码质量。
- 示例与应用：`Apps/` 提供 CesiumViewer 和 SampleData（3DTiles、glTF、KML/GPX/CZML 等测试数据）；`Documentation/` 包含 Fabric 材质、自定义着色器、离线部署等指南。
- Rust 重实现：`cesiumrust/` 是独立的 Cargo workspace，按领域驱动设计分层——`domain/*`（纯 Rust 领域模型，如 geospatial、tileset、scene、globe 等）、`ports/driven`+`ports/driving`（trait 契约）、`adapters/*`（Bevy 渲染、解码器、网络实现）、`application/cesium-app`（Bevy App 装配）、`specs/`（移植自 CesiumJS Specs 的集成测试），通过 `Cargo.toml` 的 `[workspace.dependencies]` 集中管理依赖版本。
- 依赖方向：JS 层不依赖 Rust 层；Rust 层独立编译，仅共享 Specs 数据目录用于行为一致性验证。
