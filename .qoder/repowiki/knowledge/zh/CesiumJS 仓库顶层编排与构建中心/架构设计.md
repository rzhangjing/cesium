- 工作区依赖：根 package.json 声明 `workspaces: [packages/engine, packages/widgets, packages/sandcastle]`，并以 `@cesium/engine`、`@cesium/widgets` 形式被自身引用，形成 engine→widgets→CesiumJS 的单向依赖链。
- 构建管线：`gulpfile.js` 是总入口，调用 `scripts/build.js` 中的 `buildEngine` / `buildWidgets` / `buildCesium` / `bundleWorkers` / `glslToJavaScript` / `createCombinedSpecList` 等函数；esbuild 负责 ESM/IIFE/CJS 三套产物，GLSL 经 `glsl-strip-comments` 预编译为 JS。
- 开发服务器：`server.js`（`npm start`）用 Express 启动两个同源隔离的站点——8080 端口主站 + 8081 端口镜像站，配合 `scripts/createRoute.js` 与 `ContextCache` 对 esbuild context 做增量缓存，监听 `packages/*/Source`、`Shaders`、`Specs/TestWorkers` 变化自动重建。
- 测试编排：`gulp test` 先按需 `buildCesium({iife:true})`，再用 Karma 加载 `Build/Specs/karma-main.js` 与 `SpecList.js`；`--workspace=engine|widgets` 时把代理重定向到对应包的 Source/ThirdParty/Assets/Workers，使单包 Spec 也能直接运行。
- 类型与文档：`buildTs` 按顺序对 workspace 逐个执行 `tsd-jsdoc` 生成 d.ts，再汇总生成根级 `Source/Cesium.d.ts`；`buildDocs` 以 `Tools/jsdoc/conf.json` 配置 JSDoc，并注入 `CESIUM_VERSION`、`CESIUM_PACKAGES` 环境变量供模板使用。
- 发布流水线：`release` → `buildRelease`（engine/widgets/Cesium 双产物）+ 并行 `buildTs` + `buildDocs`；`websiteRelease` 额外产出 Sandcastle 与未压缩版本；`postversion` 钩子扫描所有 package.json 中对该 workspace 的依赖并同步更新版本号。
- 代码质量：ESLint (`eslint.config.js`)、Prettier、Markdownlint、ast-grep (`sg scan`)、cloc 等工具在根脚本中统一暴露，husky 在 `prepare` 阶段安装 git hooks。
- Rust 重构并存：`cesiumrust/` 目录作为独立 Bevy 桌面端重构工程与 JS 源码并列存放，共享地理空间领域模型但走完全独立的 crate 体系，不进入 npm workspaces。
