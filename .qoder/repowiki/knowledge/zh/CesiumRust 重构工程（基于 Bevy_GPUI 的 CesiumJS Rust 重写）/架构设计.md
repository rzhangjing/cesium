采用 Cargo workspace 多 crate 结构，顶层 `Cargo.toml` 通过 `[workspace]` 声明四层依赖方向：
- Domain 层（`domain/*`，如 geospatial、scene、tileset、datasource、material 等 ~29 个 crate）：纯 Rust 无框架依赖，对应 CesiumJS `packages/engine/Source/Core/...`，每个 crate 仅依赖更底层的 domain crate（例如 `cesium-scene` 依赖 `cesium-geospatial` 与 `cesium-camera`）。
- Ports 层（`ports/driven`、`ports/driving`）：定义 trait 契约，隔离外部 IO/渲染实现。
- Adapters 层（`adapters/bevy-render`、`adapters/decoders`、`adapters/network`）：基于 Bevy 0.15 的具体实现，依赖 ports 但不被 domain 反向依赖。
- Application 层（`application/cesium-app`）：Bevy App 装配入口，组合各 domain crate 并暴露示例 showcase。
- 测试套件（`specs` crate）：作为集成测试 crate，依赖全部 domain crate，提供 `assert_approx!`、`assert_vec*_epsilon!`、`assert_mat*_epsilon!`、`assert_quat_epsilon!` 宏及 `epsilon::EPSILON1..20`、`math_consts` 常量，严格对齐 CesiumJS `toEqualEpsilon` 语义；其下 `tests/core/`、`tests/datasources/` 等目录存放从 JS Specs 移植的 Rust 测试用例。
数值精度策略：workspace 中显式禁用 glam 的 `fast-math`（注释说明 FMA 会导致与 CesiumJS 双舍入 IEEE-754 产生 1-ulp 差异），确保 bit-exact 可复现。
