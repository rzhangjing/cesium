模块遵循严格的六边形架构分层：
- 领域层（`domain/`，31 个 crate）：纯 Rust、无框架依赖，按职责划分为 geospatial/time/camera/terrain/imagery/tileset/gltf/scene/datasource/material/atmosphere/interaction/effects/shadow/crs/kml/gpx/provider/styling/globe/quadtree/primitives/animation/implicit-tiling/vector/scene-mode/performance/voxel/widgets，所有数值计算使用 f64 以保证与 CesiumJS 位级一致。
- 端口层（`ports/driven`、`ports/driving`）：定义 GpuSink/HttpFetcher/ImageDecoder/TerrainDecoder 等 IO 接口以及 TileRenderer/ImageryProvider 等应用 API 契约，领域仅依赖端口而非具体实现。
- 适配器层（`adapters/`）：`bevy-render` 通过 13 个 Bevy Plugin（Core/Camera/Tileset/Terrain/Imagery/Entity/Material/Atmosphere/Effects/Widget/Debug/FabricMaterial/DataSource）把领域数据转换为 Bevy Mesh/Texture；`decoders` 提供 image/quantized-mesh/glTF 解码；`network` 基于 ureq 实现 HTTP 获取。
- 应用层（`application/cesium-app`）：唯一含 `main()` 的组合根，注册插件并编排 orbit_camera、dynamic_globe、starfield、atmosphere_glow 等本地模块。
- 测试层（`specs/`）：从 CesiumJS 12,823 个 Specs 移植的验收测试集，作为功能正确性的唯一基准。
依赖方向严格单向：application → adapters → ports ← domain，domain 不反向依赖任何框架。
