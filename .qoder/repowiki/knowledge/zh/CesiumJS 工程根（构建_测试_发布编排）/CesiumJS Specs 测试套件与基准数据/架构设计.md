目录按测试运行环境与被测资源两层组织：
- 顶层 `Specs/` 为基于 Jasmine 的浏览器单元/集成测试入口，`spec-main.js` 解析 URL 参数（`category`、`not`、`webglValidation`、`webglStub`、`release`）并调用 `customizeJasmine.js` 注入分类过滤、默认匹配器与自定义相等比较；`karma.conf.cjs` 通过 Karma + jasmine 框架加载 `Build/CesiumUnminified` 产物与 `SpecList.js` 动态生成的用例清单，将 `Specs/Data/**` 和 `TestWorkers/**/*.wasm` 以代理 `/base/...` 暴露给测试。
- `Specs/e2e/` 使用 Playwright（`playwright.config.js`）在 Chromium/Firefox/WebKit 三引擎下启动真实 dev server（`npm run start -- --production`），通过 `toHaveScreenshot` 做像素级回归比对，配合 `CesiumPage.js` 封装页面夹具。
- `Specs/TestWorkers/` 提供 Worker/WASM 场景下的异常与传输用例；`Specs/TypeScript/` 用于 TS 编译期断言。
- `Specs/Data/` 是纯静态资源层，按格式分目录：`Cesium3DTiles/`（Batched/Instanced/PointCloud/Vector/GaussianSplats/Voxel/Metadata/Hierarchy/Implicit 等子集）、`Models/glTF-2.0/`（数百个 glTF 用例含 Draco/Meshopt/KTX2/PropertyTexture 等扩展）、`CesiumTerrainTileJson/`、`KML/`、`GPX/`、`Images/`、`EnvironmentMap/`、`Videos/`、`WMS/`、`ArcGIS/`、`GoogleEarthEnterprise*`、`TMS/` 等，每个子目录对应一组 spec 的输入数据集。
依赖方向单向：测试代码 → 构建产物 `Build/Cesium*` → 读取 `Specs/Data/*` 静态资源；无业务源码耦合。
