本模块按职责拆分为三个子目录，彼此无运行时依赖，仅通过 Node 脚本被根级 gulp 任务编排：
- `scripts/`：核心构建入口。`build.js` 基于 esbuild 实现多阶段流水线——先由 `glslToJavaScript` 扫描 `packages/*/Source/Shaders/**/*.glsl` 并输出带版权头的 JS 字符串模块，再由 `createIndexJs`/`createCesiumJs` 用 globby 动态聚合 engine/widgets 两个 workspace 的源码生成 `index.js` 与 `Source/Cesium.js` 总入口，最后以 ESM/IIFE/CJS 三种格式产出到 `Build/`；同时支持 `bundleWorkers`（将 Workers 内联为 base64 注入或独立 split）、`bundleCombinedSpecs`（Specs 测试包）以及 `copyEngineAssets`/`copyWidgetsAssets` 静态资源拷贝。
- `Tools/`：辅助工具。`ast-grep/rules/*.yml` + `tests/*.test.yml` 定义代码风格规则及其快照测试；`jsdoc/` 包含自定义 publish 流程、cesium_template 模板与 tags 扩展，配合 `conf.json`/`ts-conf.json` 生成 API 文档；`rollup-plugin-strip-pragma/index.js` 是遗留 rollup 插件，而 `scripts/build.js` 中已内联了等价的 `stripPragmaPlugin`（匹配 `//>>includeStart(...)/includeEnd(...)` 注释块），两者正则一致，体现从 rollup 向 esbuild 迁移的过渡态。
- `launches/*.launch`：VSCode 外部工具 launch 配置，统一指向 `gulp build`、`gulp minify`、`gulp release` 等任务，作为 IDE 一键触发入口。
依赖方向单向：`scripts/*` → `packages/{engine,widgets,sandcastle}` 源码与 Build 产物；`Tools/jsdoc` 仅消费 Source 与 JSDoc 注释；`launches` 仅消费 npm 脚本。
