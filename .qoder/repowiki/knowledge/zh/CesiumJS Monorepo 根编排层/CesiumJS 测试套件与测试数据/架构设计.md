模块按运行环境划分为三层：
- 浏览器单元层：`spec-main.js` 作为入口，通过 URL query（`category`/`not`/`webglValidation`/`webglStub`/`debugCanvasWidth`）驱动 `customizeJasmine.js` 重写 `describe` 实现分类过滤，并注入 `addDefaultMatchers`、`equalsMethodEqualityTester` 等自定义断言；Karma 配置在 `karma.conf.cjs` 中声明加载 `Build/CesiumUnminified/Cesium.js`、`Build/Specs/SpecList.js` 及 `Specs/Data/**` 静态资源。
- Node 端冒烟层：`test.mjs` 直接 import `cesium` npm 包，调用 `createWorldTerrainAsync`/`sampleTerrain` 做最小可用验证；`TestWorkers/` 下的 Worker/WASM 脚本用于 Worker 通信与 WebAssembly 能力测试。
- E2E 视觉回归层：`e2e/playwright.config.js` 启动 `npm run start -- --production` 作为 webServer，以 Chromium/Firefox/WebKit 三项目并行执行 `*.spec.js`，使用 `toHaveScreenshot` 进行像素级对比，`CesiumPage` 封装页面初始化与 `CESIUM_BASE_URL` 注入。
- 测试数据层：`Data/` 下按协议/格式分目录组织（`Cesium3DTiles/*`、`Models/glTF-2.0/*`、`CZML/*`、`KML/*`、`WMS/*`、`Images/*`、`Videos/*` 等），每个子目录对应一个或一组 spec 的输入用例，由 Karma 通过 `/base/Specs/Data` 代理暴露给浏览器。
依赖方向单向：所有 spec 仅依赖 `../packages/engine/index.js` 导出的 API 与 `Specs/` 内工具函数，不反向依赖被测产物源码。
