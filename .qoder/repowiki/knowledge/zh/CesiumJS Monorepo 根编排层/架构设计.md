根目录不承载业务逻辑，而是把四个子模块（cesiumjs_core、packages、apps_and_samples、specs_and_tests）以及 build_tools 串联成一条端到端流水线：
- `package.json` 声明 npm workspaces 指向 `packages/engine`、`packages/widgets`、`packages/sandcastle`，并通过 `dependencies` 以 `@cesium/engine`、`@cesium/widgets` 引入已发布的 Rust crate，使 cesiumjs_core 入口在浏览器/Node 下都能加载到 Rust 编译产物。
- `server.js` 是统一的开发入口（`npm start`），非生产模式下调用 `scripts/build.js` 中的 `buildEngine/buildWidgets/buildCesium` 增量打包，并用 chokidar 监听 engine/widgets Source 与 Specs 变更，自动重建 IIFE/ESM/Workers 并刷新两个 Express 服务（8080 主站 + 8081 Sandcastle 镜像源隔离）。
- `gulpfile.js` 暴露 `build`/`buildWatch`/`test`/`coverage`/`release` 等任务，按相同顺序串行调用 engine→widgets→Cesium 构建，再启动 Karma+Jasmine 或 Playwright E2E；`websiteRelease`/`buildRelease` 负责生成 Build/CesiumUnminified 与 zip/tgz 制品。
- `tsconfig.json`、`eslint.config.js`、`.gitignore` 为所有子包提供统一的类型检查、ESLint 规则与忽略策略，确保 engine/widgets/apps/specs 共享同一套质量门禁。
- 子模块之间不直接互相 import，而是通过 `Build/` 输出目录和 `@cesium/*` npm 依赖契约通信，根层仅负责把它们装配起来。
