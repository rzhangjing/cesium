# 地理计算使用 f64 双精度，仅在 GPU 边界降为 f32

_来源：a5ed267 → 6049380 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
CesiumJS 核心数学库全部使用双精度浮点数进行经纬度、ECEF 坐标、矩阵运算等地理空间计算，避免大坐标下的浮点精度丢失问题。Bevy/wgpu 渲染管线默认使用 f32。

## 决策驱动
- 全球尺度坐标精度要求
- 与 CesiumJS 测试结果一致性
- GPU 资源限制

## 备选方案
- **全栈 f64** _（已否决）_ — 优点：最高精度，与 CesiumJS 行为一致；缺点：GPU 不支持 f64，性能开销大，内存占用翻倍
- **全栈 f32** _（已否决）_ — 优点：GPU 原生支持，性能好；缺点：全球坐标下经纬度转换精度不足，高程误差可达米级
- **Domain f64 + Adapter 边界降精度** — 优点：地理计算精度保证，GPU 兼容性良好，内存可控；缺点：需要在每个 Adapter 边界显式转换，容易遗漏

## 决策
Domain 层所有几何计算、坐标转换、矩阵运算统一使用 glam::DVec3/DMat4/DQuat（f64），仅在 GpuMeshSink/GPU 资源上传时通过 Adapter 转换为 f32 格式送入 wgpu。

## 影响
确保全球范围坐标精度与 CesiumJS 对齐；GPU 内存占用合理；但每次 GPU 交互都需要精度转换，且调试时需关注 f64→f32 的精度损失。
