- 每个 Rust 测试文件顶部以单行注释标明来源 JS Spec 路径（如 `//! Core/MathSpec.js → Rust integration tests`），保持一一对应关系。
- 数值断言统一使用 `assert_approx!` 宏配合 `epsilon::EPSILON*` 常量，而非直接 `==` 比较浮点数。
- 测试模块按 CesiumJS 源码目录结构镜像组织：`core/`、`datasources/`、`renderer/`、`scene/`、`widgets/` 等子目录分别对应该模块的 Spec 分类。
- Rust specs crate 通过 `Cargo.toml` 显式声明对所有 domain crate 的依赖，确保测试覆盖完整领域模型，不引入未声明的外部依赖。
- JS Spec 文件通过 `describe/it` 命名空间组织，Rust 侧使用 `#[test] fn test_*()` 函数名风格，保持语义一致的测试命名约定。
