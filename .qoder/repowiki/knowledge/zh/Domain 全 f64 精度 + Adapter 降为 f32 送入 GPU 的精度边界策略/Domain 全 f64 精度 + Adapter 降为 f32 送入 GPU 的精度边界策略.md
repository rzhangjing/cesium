# Domain 全 f64 精度 + Adapter 降为 f32 送入 GPU 的精度边界策略

_来源：56a9b8e → 12aeaaa 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
地理空间计算（椭球、投影、射线相交、三角剖分）对数值稳定性要求极高，而 GPU 着色器普遍使用 f32，需要在某处做精度切换。

## 决策驱动
- 数值稳定性优先于性能
- GPU 管线天然 f32
- 避免在热点路径频繁类型转换

## 备选方案
- **Domain 全 f64，仅在 Adapter 边界做一次 f64→f32 转换** — 优点：算法正确性有保证；转换集中一处便于审计；缺点：内存占用翻倍；每次渲染都要复制+转换
- **全局使用 f32** _（已否决）_ — 优点：内存带宽减半；与 GPU 一致；缺点：长距离坐标累积误差大；投影/相交计算可能不稳定

## 决策
所有 domain 模块内部统一使用 f64（glam 的 DVec3/DMat4/DQuat），仅在 adapters/bevy-render 中将顶点/法线等数据降精度为 f32 写入 Bevy Mesh。

## 影响
内存压力增大（尤其是地形网格、点云），但保证了 WGS84 尺度下的数值稳定；后续可在热点路径引入 SIMD 批量转换以缓解带宽压力。
